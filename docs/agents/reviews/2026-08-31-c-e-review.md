## BLOCKER

**B1 — New "Lagerplan" tile 404s in the admin shell.**
`app/(admin)/inventory/page.tsx:50` — the tile is built from the shared `basePath` returned by `operationsBasePath('/inventory', '/neo/app/lager')` (`lib/routing/operations-base-path.ts`), but only `app/(neo)/neo/app/lager/plan/` was created; there is no `app/(admin)/inventory/plan/`. Opening `/inventory` (Mise OS shell) and clicking "Lagerplan" yields a 404. This is the primary entry point of the whole packet.
*Fix:* add `app/(admin)/inventory/plan/page.tsx` re-exporting the Neo page (the mirror pattern `app/(neo)/neo/app/lager/shelves/page.tsx` used before this diff), or render the tile only when `basePath` is the Neo path.

**B2 — The migration's hierarchy trigger breaks the still-reachable legacy shelf editor.**
`supabase/migrations/20260831140000_inventory_warehouse_plan.sql:32` (+ trigger at `:42`) raises `inventory place requires a unit` for any `place_kind='place'` row without a parent. `place_kind` defaults to `'place'` (`:4`), and `app/(admin)/inventory/shelves/editor.tsx:29` — reachable at `/inventory/shelves`, still linked from `app/(admin)/inventory/page.tsx:51` — inserts `inventory_shelves` rows with neither `parent_shelf_id` nor `place_kind`. After this migration every "Fach anlegen" in that editor fails with a raw English database exception. Existing functionality is regressed with no migration of the caller.
*Fix:* treat a parentless row as a `unit` in the trigger (or allow parentless places), or update the legacy editor to pass `place_kind`/`parent_shelf_id`.

**B3 — Movement `typ` vocabulary diverges from the canonical one.**
`supabase/migrations/20260831140000_inventory_warehouse_plan.sql:83,84,87` writes `'zugang'`, `'entnahme'` and `'umlagerung'`. The canonical vocabulary rendered by the Bewegungen audit trail is `eingang | ausgang | inventur | schwund | korrektur | transfer | verbrauch` (`app/(admin)/inventory/movements/page.tsx:11-19`), and `scripts/migrations/073_inventory_tenant_integrity.sql` uses `'inventur'`. Consequence: `TYP_LABELS[m.typ] ?? { label: m.typ }` (`movements/page.tsx:49`) falls through and prints the raw technical string as the badge; and if `stock_movements.typ` carries a CHECK constraint over the existing vocabulary (the base DDL is not in this repo, so it could not be confirmed here), **every** Einbuchen/Entnehmen/Umlagern/Zählen from the QR page fails at runtime.
*Fix:* use `eingang` / `ausgang` / `transfer` / `inventur`.

**B4 — The count action re-introduces the parallel stock-write path that migration 074 removed.**
`supabase/migrations/20260831140000_inventory_warehouse_plan.sql:73,80,87` — for `p_action='count'` the RPC updates `inventory_items.letzte_inventur` and inserts into `stock_movements` directly. `scripts/migrations/074_inventory_count_single_movement.sql` exists precisely to make `inventory_counts` (via `trg_inventory_count_movement`) the single owner of that pair, and `tests/inventory/inventory-integrity.test.ts:30-31` encodes the invariant. The scan count therefore never reaches `inventory_counts`, so the Inventuren/Abweichungen screens for management show nothing — the packet's "deviations are listed for management" acceptance criterion is unmet — and two competing count paths now exist (coordination rule 5, "no parallel systems"). The integrity test still passes only because it asserts against the *074 file*, not against new migrations.
*Fix:* have the count action insert into `inventory_counts` and let the canonical trigger own the movement and the stock update.

## MAJOR

**M1 — Raw English PostgreSQL exception text is shown to the user.**
`app/api/inventory/warehouse/route.ts:18` and `:27` return `error.message` verbatim; `app/(neo)/neo/app/lager/platz/[token]/place-actions.tsx:11` and `app/(neo)/neo/app/lager/plan/warehouse-plan.tsx:20` render it as the toast description (`toastError(title, description)`, `components/ui/toaster.tsx:21`). Staff see strings such as `actor may not manage inventory plan`, `inventory stock cannot become negative`, `inventory action is invalid`. Violates the owner order (point 7: no technical data anywhere in the normal UI) and the German-copy rule.
*Fix:* map RPC error identifiers to German messages in the route and never forward `error.message`.

**M2 — A raw UUID is written into a user-visible movement note.**
`supabase/migrations/20260831140000_inventory_warehouse_plan.sql:84`: `'Umlagerung Eingang von '||p_place_id::text`. `notiz` is displayed at `app/(admin)/inventory/movements/page.tsx:62`.
*Fix:* look up and use the source place's `name` (the outgoing row at `:83` already does this for the target).

**M3 — "Bestellvorschläge" is not implemented; the unit tests cover no production code.**
`lib/inventory/warehouse-plan.ts` exports `validateWarehouseHierarchy` (`:8`), `nextStock` (`:30`), `inventoryDeviation` (`:38`) and `groupReorderProposals` (`:44`); a repo-wide grep shows the only importer is `tests/inventory/warehouse-plan.test.ts:2`. The real logic lives in PL/pgSQL in the migration, and `app/api/inventory/auto-reorder/route.ts` is untouched, so the packet requirement "extend `api/inventory/auto-reorder` so that places under Soll produce a proposal line grouped by supplier" is unmet. The 5 new unit tests exercise a TypeScript re-implementation that nothing calls.
*Fix:* wire the helpers into the API/reorder path (or delete them) and test the path that actually runs.

**M4 — Duplicate nav tile pointing at the same page; the flat shelf editor is silently removed from Neo.**
`app/(admin)/inventory/page.tsx:51` keeps "Regalplätze — Bestehende Plätze verwalten", but `app/(neo)/neo/app/lager/shelves/page.tsx:2` now `redirect('/neo/app/lager/plan')`. In the Neo shell the two adjacent tiles open the identical page and the second tile's description is untrue. The rename / reorder / delete capabilities of `ShelvesEditor` are gone from Neo, and the new plan offers create only — no rename, no delete (the API supports `p_id` updates at `route.ts:13`, but no UI ever sends it). The owner requirement is "Räume, Regale … anlegen **und benennen**".
*Fix:* drop the duplicate tile and add rename/delete to the plan before removing the editor.

**M5 — Transfer writes factually wrong before/after values into the ledger.**
`supabase/migrations/20260831140000_inventory_warehouse_plan.sql:83-84` records `vorher=v_before, nachher=0` for the outgoing row and `vorher=0, nachher=v_before` for the incoming row, while `:79` leaves `letzte_inventur` at `v_after = v_before`. The audit trail claims the stock dropped to zero and came back; it never changed.
*Fix:* record the item's real before/after stock, or model the place balance explicitly.

**M6 — No printable label; the QR endpoint returns a bare SVG.**
`app/api/inventory/warehouse/[token]/qr/route.ts:16-17` returns only the QR graphic — no place name, no room, no location. `app/(neo)/neo/app/lager/platz/[token]/page.tsx:18` nevertheless labels it "QR-Etikett öffnen und drucken", and the plan page offers no bulk label sheet. The packet requires "a printable label sheet (reuse the existing print/QR routes)"; `app/api/print` was not reused.
*Fix:* add a print view rendering name + room + QR, and a per-unit/per-room sheet from the plan.

## MINOR

**m1 — API route performs almost no input validation.**
`app/api/inventory/warehouse/route.ts:8-29` validates only that `locationId` is a string; `intent`, `action`, `amount`, `placeId`, `itemId`, `areaId` are forwarded untyped. `amount: null` survives the RPC guard at migration `:69` (`p_amount<0` and `p_amount=0` both evaluate to NULL, so the `if` does not fire) and reaches `letzte_inventur = null` at `:80`.
*Fix:* validate types in the route and require a finite, non-negative `amount`.

**m2 — Umlagern is impossible for an empty place and is not a search/scan picker.**
`app/(neo)/neo/app/lager/platz/[token]/place-actions.tsx:12` preloads a `readOnly` amount equal to `item.letzte_inventur ?? 0`; at stock 0 the RPC rejects with `inventory action is invalid` (migration `:69`). The target chooser is a plain `<select>` of every place in the location — the packet asked for "search or scan".
*Fix:* hide/disable Umlagern at 0 stock and add a searchable target field.

**m3 — Status chip says "ok" for a place whose products are all at zero.**
`app/(neo)/neo/app/lager/plan/warehouse-plan.tsx:22`: `empty` is `stock.length===0` only, so quantities are ignored.
*Fix:* treat a total quantity of 0 as `leer`.

**m4 — Form labels are not associated with their controls.**
`warehouse-plan.tsx:22` and `place-actions.tsx:12` render `<Label>` without `htmlFor` and without wrapping the input; the "Optionaler Hinweis" input has no label at all, and both `<select>` elements are unlabelled for screen readers.
*Fix:* add matching `id`/`htmlFor` pairs.

**m5 — Plan page pulls the whole tenant unfiltered and casts the result away.**
`app/(neo)/neo/app/lager/plan/page.tsx:10-14` loads every area, every shelf and every active item of the tenant with no location filter and no pagination, then passes them through `as any` (`:15`).
*Fix:* scope by location (or paginate per room) and type the rows.

**m6 — Deleting a unit now fails silently.**
Migration `:3` adds `parent_shelf_id … on delete restrict`; `app/(admin)/inventory/shelves/editor.tsx:45` never inspects the delete result, so removing a unit that holds places (including the migration-created "Bestehende Lagerplätze") does nothing with no message.
*Fix:* surface the error, or offer to detach the places first.

**m7 — External link without `rel`.**
`app/(neo)/neo/app/lager/platz/[token]/page.tsx:18` uses `target="_blank"` without `rel="noopener noreferrer"`.
*Fix:* add the `rel` attribute.

**m8 — New components violate the repository's code-style conventions.**
`warehouse-plan.tsx:20,22`, `platz/[token]/page.tsx:11,18` and `place-actions.tsx:11,12` compress entire components and queries onto single 2–4 kB lines with no spacing, unlike every neighbouring file (e.g. `app/(admin)/inventory/shelves/editor.tsx`). This makes future diffs unreviewable and works against the coordination rule on minimal, reviewable diffs.
*Fix:* format to the surrounding style.

## NOTE

**n1 — Place page is tenant-scoped but not location-scoped.**
`app/(neo)/neo/app/lager/platz/[token]/page.tsx:11` filters on `area.location.tenant_id` only, so an employee of location A can read location B's place page. Writes are still refused by the RPC (migration `:68`), and this matches the pre-existing tenant-wide policy `inventory_shelves_read_073` (`scripts/migrations/073_inventory_tenant_integrity.sql:49`), so it is not a new leak — but the packet asks for location scope on the staff surface.

**n2 — Printed QR may encode an internal origin.**
`app/api/inventory/warehouse/[token]/qr/route.ts:15` derives the URL from `new URL(req.url).origin`. Behind a proxy or in a preview deployment the printed label can be permanently wrong. Prefer the configured public site URL.

**n3 — Coordination rules 1 and 2 are met.**
The migration sits at `supabase/migrations/20260831140000_…`, inside C-E's reserved `20260831140000–20260831149999` range and in the same directory as the other Vollausbau migrations; it uses an explicit `begin;`/`commit;`, `add column if not exists`, `create … if not exists`, `drop constraint if exists` and guarded backfills, and is re-runnable. The backfill inserts the "Bestehende Lagerplätze" units *before* the trigger is created (`:13` vs `:41`), so it is not blocked by its own validation. `app/(neo)/neo/app/shell.tsx` was not touched, and RPC grants correctly `revoke … from public,anon,authenticated` and grant to `service_role` only (`:93-97`).

**n4 — The report is honest about what was not tested.**
The OPEN ITEMS section correctly states that the migration and RPCs were never executed and that the authenticated create → scan → book/withdraw/count flow is not live-tested; the Playwright spec (`tests/e2e/warehouse-plan.spec.ts`) genuinely only asserts the login-redirect and the unauthenticated-write boundary, which is what the report says. The vitest and tsc figures were reproduced exactly. The overstatement is in the CHANGES/DB CHANGES sections, which describe capabilities (deviation listing, reorder proposals, printable label, rename/delete) that B4, M3, M4 and M6 show are not present.
