## Procedure (mirror attempt 6 exactly, same evidence style)

1. `git bundle create /tmp/vollausbau-<CANDIDATE>.bundle 87320087..<CANDIDATE>`,
   verify with `git bundle verify`, scp via the jump host, record SHA-256.
2. Backup: `docker exec supabase-db pg_dump -U supabase_admin -d postgres -Fc`
   → `/opt/mise/backups/vollausbau-pre-<UTC>.dump`, mode 0600, record size
   and SHA-256 and `pg_restore --list | wc -l`.
3. `cd /opt/mise/backoffice && git fetch /tmp/…bundle && git merge --ff-only <CANDIDATE>`;
   no GitHub fetch/rebase.
4. Apply the NEW migrations in filename order with
   `docker exec -i supabase-db psql -U supabase_admin -d postgres -v ON_ERROR_STOP=1 < file`
   — each file has its own explicit transaction. Stop at the first failure,
   report, and leave the app untouched (previous release still serving).
   After all files: run the verification queries listed in
   `docs/agents/deploy/2026-08-31-migrations.md`.
5. Run `/opt/mise/auto-deploy.sh` (the fixed one; verify it still tags
   `mise-backoffice:previous` before switching). Wait for the candidate
   container to be `running` with restart count 0 and HTTP 200 on `/login`.
6. Smoke on the public URL: `/login` 200, unauthenticated
   `/api/cron/operational-escalations` 401, and one GET per new area returns a
   redirect-to-login (307/302) not 500: `/neo/app/tests`, `/neo/app/lager/plan`,
   `/neo/app/ablaeufe/aufgaben`, `/neo/app/dienstplan`, `/neo/app/schulungen`,
   `/neo/app/mitarbeiter`. Check `docker logs --since 5m` of the new container
   for errors.
7. Record everything (commit ids, hashes, sizes, container ids, tags, disk
   before/after, exact outputs) in a new HANDOFF section
   „Production deployment — Vollausbau 2026-08-31" plus the rollback recipe
   (previous image tag + immutable ID, backup path). Commit that HANDOFF
   change on the integration branch locally.
